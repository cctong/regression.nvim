==============================================================================
1. Introduction                                      *regression-introduction*

regression.nvim records a known-good Neovim snapshot and compares the current
state with it. Snapshots include Neovim version, adapter status, startup time,
errors, active LSP clients, health messages, and plugin revisions.

lazy.nvim is the default plugin-manager adapter. Set `adapter = "pack"` to use
Neovim 0.12+ |vim.pack|.

==============================================================================
2. Setup                                                    *regression-setup*

Call setup after the plugin manager has been configured: >lua

  require("regression").setup({
    profile = "default",
    adapter = "lazy", -- or "pack"
    startup = {
      enabled = true,
      percent_threshold = 0.25,
      absolute_threshold_ms = 20,
    },
    health = { enabled = true },
    bisect = { timeout_ms = 60000, settle_ms = 1000 },
  })
<

The baseline is stored under stdpath("state")/regression.nvim by default.

==============================================================================
3. Commands                                              *regression-commands*

                                                        *:NvimBaseline*
:NvimBaseline
        Capture the current state as known-good. Refuses to overwrite an
        existing baseline.

                                                       *:NvimBaseline!*
:NvimBaseline!
        Replace the existing baseline.

                                                      *:NvimRegression*
:NvimRegression
        Capture the current state, compare it with the baseline, and open the
        report in a scratch split. Press |q| to close the report.

                                                          *:NvimBisect*
:NvimBisect
        Binary-search changed plugins, then the culprit plugin's commits,
        using headless probes. See |regression-bisection|.

==============================================================================
4. Bisection                                            *regression-bisection*

Bisection probes plugin revisions from temporary git worktrees so installed
checkouts stay untouched. Plugins loaded from a custom dir outside
stdpath("data") still use an in-place checkout. It refuses dirty repositories,
verifies baseline revisions, and removes the worktrees when it finishes.

Bisection first searches the set of changed plugins, then the commits inside
the likely culprit. It assumes a single primary culprit. Do not run plugin
manager updates at the same time.
