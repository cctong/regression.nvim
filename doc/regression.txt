==============================================================================
1. Introduction                                      *regression-introduction*

regression.nvim records a known-good Neovim snapshot and compares the current
state with it. Snapshots include Neovim version, adapter status, startup time,
errors, active LSP clients, health messages, config files, and plugin revisions.

lazy.nvim is the default plugin-manager adapter. Set `adapter = "pack"` to use
Neovim 0.12+ |vim.pack|.

==============================================================================
2. Setup                                                    *regression-setup*

Call setup after the plugin manager has been configured: >lua

  require("regression").setup({
    profile = "default",
    adapter = "lazy", -- or "pack"
    startup = {
      enabled = true,
      percent_threshold = 0.25,
      absolute_threshold_ms = 20,
    },
    health = { enabled = true },
    bisect = { timeout_ms = 60000, settle_ms = 1000 },
  })
<

The baseline is stored under stdpath("state")/regression.nvim by default.
Leave bisect.test unset for automatic comparison. See
|regression-bisect-test|.

==============================================================================
3. Commands                                              *regression-commands*

                                                        *:NvimBaseline*
:NvimBaseline
        Capture the current state as known-good. Refuses to overwrite an
        existing baseline.

                                                       *:NvimBaseline!*
:NvimBaseline!
        Replace the existing baseline.

                                                      *:NvimRegression*
:NvimRegression
        Capture the current state, compare it with the baseline, and open the
        report in a scratch split. Press |q| to close the report.

                                                          *:NvimHealth*
:NvimHealth
        Check the regression.nvim setup: Neovim version, Git, adapter
        availability, storage directory, and baseline validity. Opens the
        results in a scratch split.
        The same checks run under |:checkhealth| as `:checkhealth regression`.

        If |:NvimHealth| reports an invalid or unsupported baseline, update
        regression.nvim or use |:NvimBaseline!| to replace it.

                                                          *:NvimBisect*
:NvimBisect
        Binary-search changed plugins, then the culprit plugin's commits,
        using headless probes. See |regression-bisection|.

==============================================================================
4. Bisection                                            *regression-bisection*

Bisection probes plugin revisions from temporary git worktrees so installed
checkouts stay untouched. Plugins loaded from a custom dir outside
stdpath("data") still use an in-place checkout. It refuses dirty repositories,
verifies baseline revisions, and removes the worktrees when it finishes.

Bisection first searches the set of changed plugins, then the commits inside
the likely culprit. It assumes a single primary culprit. Do not run plugin
manager updates at the same time.

                                                      *regression-bisect-test*
bisect.test is an optional module name. Leave it unset for automatic snapshot
comparison.

Put the module under your config's lua/ directory. It returns a function.
Each probe runs that function in the child after opening the current file and
waiting for LSP clients. Return true when the revision is healthy. Extra
returns after true are ignored. Return false, with an optional string reason,
when the bug is reproduced.

That function is the only predicate for the all-current check, the
all-baseline check, the plugin search, and the commit search. Startup, error,
LSP, and health comparisons are not used.

A failed load (missing module or syntax error), a bad return, an exception, a
child-process failure, or a timeout stops the bisect and does not name a
culprit. vim.wait() may be used inside the function and must finish within
timeout_ms.

The example uses a scratch buffer and does not write a file: >lua

  -- lua/regression_checks/formatting.lua
  return function()
    local buf = vim.api.nvim_create_buf(false, true)
    vim.api.nvim_buf_set_lines(buf, 0, -1, false, {
      "function example()",
      "return true",
      "end",
    })
    vim.api.nvim_buf_call(buf, function()
      vim.bo.filetype = "lua"
      vim.bo[buf].shiftwidth = 2
      vim.bo[buf].expandtab = true
      vim.cmd("silent normal! gg=G")
    end)
    local lines = vim.api.nvim_buf_get_lines(buf, 0, -1, false)
    vim.api.nvim_buf_delete(buf, { force = true })
    if lines[2] ~= "  return true" then
      return false, "indent command did not indent the body"
    end
    return true
  end
<

Point setup at that module: >lua

  require("regression").setup({
    bisect = { test = "regression_checks.formatting" },
  })
<
